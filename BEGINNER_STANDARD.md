# LEARN — Conceptual self-sufficiency standard (2026-10-22)

**Aim:** any reader who has never studied computing should be able to understand any one infographic independently. Avoid assuming familiarity with other LEARN lessons.

Each future or revised **English and Romanian** infographic should: 

1. Say **what this thing is** in familiar language before using technical terminology.
2. Explain **why it exists**: the problem it solves for a human or a computer.
3. Show **one concrete example** in common experience, before the code or infrastructure diagram.
4. **Define every technical term needed for the explanation**, including nested prerequisites; do not define “cache” using an unexplained word such as “latency”.
5. Expand every acronym **at first use**, and give its everyday meaning in the language of the sheet.
6. Explain each important symbol or line of code shown; even `for`, `=`, brackets, loops and variables are new concepts to a beginner.
7. Explain the diagram's arrows and what changes between stages. 
8. Clearly distinguish metaphors, simplified illustrations, and how the system really behaves.
9. Name the trade-off or a realistic limitation without introducing unexplained jargon.
10. Offer an **optional individual discovery** that needs no teacher, account or specialized software.
11. Remain readable when printed on A4; avoid a tiny glossary that requires magnification. If all prerequisites do not fit, redesign the graphic or create a fully explained multipage variant rather than deleting explanations.
12. Preserve permanent lesson IDs and QR links, publication rights and standalone bilingual access.

## Review procedure

A topic is **not marked as self-sufficient** until a beginner can correctly explain the main sequence and central idea without visiting another lesson or dictionary. Check both language versions independently. A machine scan can flag jargon and abbreviations, but cannot prove comprehensibility.
